# Phase G4 — Multi-Material Terrain Texture Repetition Correction

## Scope and outcome

Phase G4 adds a shared, presentation-only repetition correction for ordinary
terrain surfaces while preserving the existing G1–G3 grass path. The reviewed
default enables the correction for sand, dirt, stone, and mud. Snow and gravel
remain unchanged by default because the tested correction did not produce a
clear visual improvement for those materials. Water remains on its established
liquid shader branch.

No terrain generation, simulation, collision, picking, persistence, water,
cliff-face texture, or save-schema code was changed. `main.tscn` and
`_reference` were not modified by Phase G4.

## Investigation and root cause

Every catalog surface uses a 32×32 source image. Each material's four visual
variants are generated by tinting, brightness, and contrast changes to the same
image. The variant blend changes colour over broad world-space regions but all
variants retain the same motif phase. Consequently, the source pattern repeats
at exactly 32 pixels regardless of variant blending.

| Material | Source and visible issue | Important features | G4 decision |
|---|---|---|---|
| Water | Repeating source exists, but the liquid branch already adds world-space bands, shoreline treatment, calm tinting, and optional motion | Ripples, shoreline and liquid motion | Unchanged; a ground-surface warp would interfere with the dedicated liquid treatment |
| Sand | Sparse grains form a clear diagonal lattice across large regions | Fine grains and warm palette | Continuous phase warp enabled at restrained strength |
| Dirt | Dark pores repeat in diagonal/checkerboard rows | Specks, soil colour variation | Continuous phase warp enabled |
| Grass | Source background lattice was already addressed by G3 | G1 clustered blades, G2 colour variation, G3 reconstructed background | G3 path preserved exactly; G4 is disabled on grass |
| Stone | Horizontal crack/dash groups repeat in rigid rows | Crack shapes and cool stone palette | Continuous phase warp enabled at reduced strength |
| Snow | Very low-contrast diagonal shading is visible only on close inspection and reads naturally at gameplay scale | Clean snow field and pale-blue shading | Available but disabled by default; processing was not a clear improvement |
| Mud | Dark marks repeat in a regular diagonal field | Pores, clods, brown palette | Continuous phase warp enabled |
| Gravel | Dense high-contrast grains expose the tile strongly | Individual stones and dense granular character | Available but disabled by default; stronger warps replaced the grid with visible waves and were rejected |

The G3 grass reconstruction is intentionally not generalized. Its threshold and
clear-colour assumptions describe the grass artwork only and would erase stone
cracks, dirt marks, sand grains, snow shading, or gravel stones.

## Evaluated techniques

- Per-tile rotation/mirroring preserved source pixels and used no extra texture
  samples, but produced visible tile-edge blocks on stone and gravel. This
  implementation was rejected after the first visual matrix.
- Stronger continuous phase warping removed hard tile seams, but bent dense
  stone/gravel details into visible waves. Those preliminary defaults were also
  rejected.
- The retained solution uses a low-frequency, continuous world-space phase warp
  with material-specific strength and scale. It preserves source pixels,
  palettes, and feature shapes while gradually shifting their repeated phase.
  Reduced strengths avoid the wave artifact seen in the preliminary pass.

## Implementation

`terrain_variation.gdshader` now accepts a global material correction state,
strength, and scale. Two deterministic smooth fields offset the source sampling
coordinate. Inputs use quantized absolute world pixels and the existing
material/world seed, so the result is stable during camera movement, independent
of chunk construction order, and continuous at chunk boundaries.

`TerrainSurfaceFactory` translates catalog eligibility and renderer overrides
into the shared material uniforms. `TerrainRenderer` owns runtime presentation
configuration and updates existing shared materials in place; switching the
feature does not invalidate or rebuild chunks. `Main` exposes the global switch
and explicit per-material switches/strengths.

Disabling the global switch bypasses the warp and restores the exact pre-G4 UV
path for all non-grass materials. Disabling an individual material restores its
prior output. Grass keeps the same G3 shader branch and settings regardless of
the G4 switch.

The implementation adds no draw calls, textures, per-chunk resources, or CPU
pixel processing. Enabled fragments perform two additional smooth-noise field
lookups before the existing texture samples.

## Final defaults

| Material | Enabled | Strength | Internal world scale |
|---|---:|---:|---:|
| Sand | Yes | 0.55 | 0.0060 |
| Dirt | Yes | 0.65 | 0.0055 |
| Stone | Yes | 0.55 | 0.0045 |
| Snow | No | 0.35 | 0.0050 |
| Mud | Yes | 0.65 | 0.0050 |
| Gravel | No | 0.35 | 0.0040 |

The global `terrain_texture_repetition_correction_enabled` default is `true`.
Snow and gravel controls remain exposed for deliberate visual experiments, but
their scene-independent defaults preserve prior output.

Visual review found:

- sand's diagonal grain lattice is substantially softened while its grains and
  palette remain intact;
- dirt and mud no longer present one rigid diagonal phase across the field;
- stone retains crack/dash details but loses the strongest row alignment;
- mixed boundaries remain aligned to the existing universal masks and show no
  new material or chunk seams;
- source pixels remain readable at 100%, 150%, and 200% zoom;
- snow and gravel retain their prior appearance by default, as intended.

The stream-away/return capture was pixel-exact. The focused validator also
checks deterministic seed/coordinate output and shared-coordinate agreement at
chunk seams.

## Performance

Matched 240-frame Compatibility-renderer measurements were taken in the same
mixed-material fixture on an NVIDIA GeForce RTX 3080:

| Mode | Average frame | p95 | p99 | Average draw calls | Static memory |
|---|---:|---:|---:|---:|---:|
| G4 disabled | 1.054 ms | 1.427 ms | 2.002 ms | 110 | 89.3799 MiB |
| G4 enabled | 1.023 ms | 1.413 ms | 1.635 ms | 110 | 89.3821 MiB |

The measured average change was within run-to-run noise (enabled was 0.031 ms
faster in this sample). Draw calls were identical. The 0.0023 MiB reported
memory difference is measurement noise; G4 creates no textures or per-chunk
resources.

## Known limitations

- G4 reduces but cannot remove every recognizable motif from a single 32×32
  source without replacing or resynthesizing the art. It deliberately preserves
  feature identity rather than smoothing details away.
- Snow remains unchanged because its existing low-contrast repetition is less
  objectionable than the tested correction.
- Gravel remains unchanged because the dense source makes continuous phase
  curvature visible. A future gravel-specific fix should start with a larger or
  genuinely stochastic source asset; that is outside this presentation-only,
  low-overhead phase.
- Cliff-face textures use the separate cliff resource factory/material path and
  were not modified because they do not share this surface sampling mechanism.
